Phase 1 aligned access width at 512bit, while the planned GPU coefficient/counter comparison uses a 32B/256bit sector unit. This PR adds a separate Phase 2-A dataset, copying the 16 width-aligned inputs and changing only WordWidth to 256bit. All 16 cases were newly executed; the four 7nm configurations were not satisfied by reuse of old logs.

Results: all 16 finished with exit 0 and empty stderr. Four fresh 7nm cases match all six Phase 1 256bit summary metrics. Relative to 512bit, read-energy reductions span 42.31–48.65% (L1) and 46.34–50.67% (L2); the response is not universally linear in width. CSVs provide absolute read/write energy, both width-ratio directions, effective pJ/bit, latency/leakage/area changes, 24 SF comparisons and direct raw/config/formula provenance. Separate data/tag organization and printed energy breakdowns preserve hierarchy and avoid double counting.

Source inspection shows WordWidth also defines modeled cache line size and affects tag/data geometry. The existing SRAM cache path cannot independently preserve a 128B line while activating a 32B sector or account for shared tag/peripheral energy across sectors. The feasibility report answers Q1–Q6 and separates effective unit normalization from GPU energy-boundary alignment. It makes no Pure Process Scaling, GPU absolute validation or private-data claim. Official NVIDIA docs were blocked by HTTP 403; generation/cache-specific details lacking evidence remain explicitly unconfirmed.

Validation: six Phase 2 tests; 16 verified resume operations without new attempts; nine generated outputs byte-identical across two analyses; all 226 Phase 1 files preserved against 26ba752; Phase 2-only SHA-256 manifest and inventory. Model sources, original ZIP and Phase 1 inputs/logs/results/reports/manifests are unchanged. Initial environment helper's generic build_command field is explicitly documented in provenance/build_recipe.json; actual compiler/linker commands and raw environment snapshots are retained.
